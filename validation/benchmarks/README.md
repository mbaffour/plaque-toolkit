# External benchmarks

Public datasets the toolkit is **tested** on but was never **trained** on. Each benchmark has a
converter that turns the dataset's own annotation format into the toolkit's
`plaque-groundtruth-v1` label files, so `app/validate.py` scores every engine the same way it
scores the authors' hand-labelled plates. Results are regenerated by script, never typed.

No dataset is committed here (licences and size). The converter prints a `manifest.csv` with
the SHA-1 of every derived image, so a run can be checked against the archived results.

| Dataset | Domain | Labels | Licence | Converter |
|---|---|---|---|---|
| **VACVPlaque** (De et al., *Sci Data* 2025; [RODARE 3003](https://rodare.hzdr.de/record/3003)) | 211 phone photos of crystal-violet-stained **6-well mammalian** plaque assays (vaccinia virus) | per-plaque and per-well instance masks | CC BY 4.0 | `vacvplaque_convert.py` |
| **OnePetri** (Shamash & Maurice 2021; Roboflow Universe) | ~2,500 **phage** plate photos | bounding boxes | CC BY-NC-SA 4.0 (login required to export) | planned — needs a manual export |

## VACVPlaque

Why it is a hard, fair test: it is a different domain (stained monolayers in 35 mm wells, not
phage lawns on 90 mm dishes), photographed on two phones, with up to ~450 plaques per well.
Nothing in the toolkit's engines, thresholds or weights ever saw it.

```bash
# unzip VACVPlaque_test.zip somewhere OUTSIDE the repo, then:
python validation/benchmarks/vacvplaque_convert.py <unzipped test folder> <scratch>/wells_x3 --scale 3
python app/validate.py <scratch>/wells_x3 --modes published,current,sensitive,precise
```

`--scale 3` is **scale normalisation**: the engines' size gates are in pixels and were tuned on
dish photos 1,500–2,800 px across, while a well on a 6-well-plate photo is ~600 px across, so at
native scale its plaques (radius ~4 px) fall under every gate. Upsampling the crop so the well
spans a dish-like diameter is the honest way to ask "does the detector transfer", separately
from "are the gates the right size". Both numbers are reported.

The mm calibration of the labels is **nominal** (a well is taken as 34.8 mm); detection metrics
are scale-free and size agreement should be read in pixels.

### Results (test split, 21 photos, 126 wells, 11,951 plaques)

See [`vacvplaque_benchmark.md`](vacvplaque_benchmark.md) for the tables (shipped engines, the
fine-tune experiment, and the pipeline with fine-tuned weights), tied to the toolkit commit and
weights digests; the per-well CSVs are under `results/vacvplaque/`.

## Environment note

`pip install ultralytics` pulls in `opencv-python` **5.x**, which then shadows the pinned
`opencv-python-headless` 4.11 that the toolkit is validated with. OpenCV 5 moves turbidity
`TRANSMITTANCE` by about 0.001 on some plates (the size CSVs are unchanged). After installing
ultralytics, run `pip uninstall opencv-python && pip install --force-reinstall --no-deps
opencv-python-headless==4.11.0.86`, and check `library_versions.opencv` in any `run_metadata.json`
before comparing numbers. The VACVPlaque tables above were produced with OpenCV 5.0 for the
Precise and detector-only rows and 4.11 for the classic-engine rows; detection counts are not
affected by the difference.
